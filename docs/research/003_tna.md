# Objective

The objective of this research is to validate the methodology used to calculate
the nominal annual rate for Argentine Treasury capitalizable instruments before
implementing it in the production financial engine.

This document preserves the historical research and records the production
decision. The official IAMC glossary is now the authoritative external
methodology source for this output.

# Excel Observation

Observed methodology:

```text
TNA = HPR × (360 / Days30/360)
```

Where:

- `HPR` is the holding period return observed in R-002;
- `Days30/360` is the remaining term from settlement to maturity as calculated
  by the reference workbook;
- `360` is the annualization basis observed in that workbook.

Current status:

- Methodology observed in the reference workbook.
- Historically selected by the project owner on 5 August 2026.
- Superseded after the 11 August 2026 IAMC report reconciliation and explicitly
  reconfirmed as rejected for production on 12 August 2026.

---

# Financial Interpretation

The workbook annualizes HPR using a simple proportional adjustment on an
observed 360-day basis. That is retained as historical evidence only and is not
the production convention.

The approved production decision uses actual residual calendar days, ACT/365
compound equivalence and `TNA = TEM × 12`. The Treasury-adapted 30/360
convention belongs to contractual VPV and must not be reused for this
secondary-market yield.

# Input and Freshness Decision

- Use an explicitly selected A3 T+1 (`plazo` 001) last or close price.
- Preserve the provider market date and settlement date.
- A current-rate view must not calculate TNA when the price-observation date
  differs from the selected purchase/market date.
- If a current A3 price is absent, report TNA as unavailable. Do not substitute
  an embedded IAMC snapshot silently.
- Keep full precision internally; presentation rounding must not feed back into
  the calculation.

The S14G6 output near 258.44% is explicitly disapproved. It resulted from
pairing the 17 July 2026 embedded price with an August residual term. That
number is an invalid temporally mixed result, not a separate formula.

---

# Current Implementation Decision

Use the IAMC-reconciled ACT/365 convention in the production financial engine,
with `TNA = TEM x 12`. Block temporally mixed inputs in the current-rate
dashboard. Preserve the earlier simple 30/360 formula only as rejected
historical research; do not treat a historical fallback price as current.

# Final Decision

Validation Status:

🟢 Validated against official IAMC glossary (owner decision, 2026-08-11)

Approved Methodology:

Selected for the project: nominal annual rate obtained as twelve times the
monthly compound-equivalent rate over an ACT/365 residual term.

Approved Formula (corrected 2026-08-11 after empirical IAMC reconciliation):

```text
residual_days = actual calendar days from settlement to maturity
TEA (TIREA)   = (1 + HPR) ** (365 / residual_days) - 1
TEM           = (1 + TEA) ** (1 / 12) - 1
TNA           = TEM * 12          # nominal annual, monthly compounding
```

**Correction note.** The previous formula `TNA = HPR × 360 / DAYS360_TREASURY`
(simple annualization on 30/360) did **not** reproduce the published IAMC TNA.
The empirical check against the BYMA/IAMC daily report for **S16O6** (10-Aug-2026)
shows IAMC uses **actual days** (the report prints 66 days, not the 30/360 value
of 65) and defines **TNA = TEM × 12** — the very form previously excluded. See
`docs/research/iamc_yield_methodology_validation_2026-08-11.md`.

The owner reconfirmed this corrected split convention on 12 August 2026: VPV
uses Treasury-adapted 30/360, while residual secondary-market yields use
ACT/365 and `TNA = TEM × 12`.

Explicitly excluded: any TNA produced from a historical price relabeled with a
later calculation date (temporal mixing).

Approved Market Convention:

Actual calendar days on a 365-day basis (ACT/365) for the secondary-market
yield, with TNA as the monthly-compounded nominal annual rate. The
Treasury-adapted 30/360 convention applies **only** to the maturity value (VPV,
issue→maturity, R-001), **not** to this yield.

Implementation Approved:

Yes - implemented in `src/financial_engine/letras_yield.py`; regression tests in
`tests/test_letras_yield.py`. The current-rate dashboard separately enforces
price/date alignment before displaying HPR, TNA, TEA or TEM.
